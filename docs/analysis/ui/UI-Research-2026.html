§1 Sidebar Navigation Patterns

Collapsible sidebars are now the standard in B2B SaaS, not a premium feature. The research is unambiguous: expanded by default, user-toggled to icon rail, preference persisted across sessions.

The specification (2026 consensus)

  • Expanded width: 220–260px. Our mock at 216px is correct.
  • Collapsed width: 56–72px (icon rail only).
  • Toggle mechanism: Click a chevron button on the sidebar border — never hover-to-expand. Linear uses [ as a keyboard shortcut alongside the click target.
  • Animation: 200–300ms cubic-bezier(.4,0,.2,1). Faster = broken. Slower = sluggish.
  • Collapsed state: Icons only, but mandatory hover tooltips revealing the full label. No tooltip = discoverability failure.
  • Logo: Collapses to the mark/icon only — no text in collapsed state.
  • Active state: The left-border accent persists in collapsed state on the icon.
  • Persistence: Save collapsed/expanded state to localStorage so it survives page reload and app restart.
  • Primary item count: 5–7 max before the IA needs restructuring. Beyond 7, the icon rail becomes a guessing game even for power users.
"The most common mistake in sidebar design is replacing text labels with icons entirely, assuming users will learn the iconography over time. In practice, this creates a learning tax." — ALF Design Group, Sidebar Design for Web Apps: UX Best Practices (2026)

§2 B2B SaaS UI Baseline — 2026

These are now table stakes. Missing any of them signals "legacy" to a 2026 buyer who uses Linear, Notion, or Vercel daily.

Information density: "purposeful density"

The direction is not "more whitespace" or "less whitespace" — it's context-sensitive density. List and table views should be compact and information-rich. Detail and edit views should have generous breathing room. The 2020 pattern of maximum padding everywhere reads as low-capability in 2026.

"Power users demand density. They want high-information interfaces that look like trading terminals, not marketing brochures." — LaderaLABS, The State of SaaS UX Design 2026

The reconciliation with "calm design": Linear looks minimal at first glance but surfaces dense information contextually on demand. The default state is clean; the information density is there when you need it. This is Strategic Minimalism — not sparse, but disciplined.

Dark mode: no longer optional

"Dark mode is no longer a feature. It's infrastructure." Pure black (#000) is wrong — the correct implementation is #121212–#14161C (warm-tinted near-black). Our mock uses #14161C — correct. The per-theme dark primary values are also correct (lighter and more vibrant on dark surfaces).

Command palette: table stakes

Every B2B SaaS product with more than 10 features is expected to have a command palette as of 2026. SaaSUI.Design: "how to design a command palette has become a standard design interview question" — a reliable signal that a pattern has crossed from innovation to expectation. GitHub attempted to put their command palette behind a feature flag in 2025 and faced immediate public backlash, reversing the decision.

✓ Mock has ⌘K command palette

Typography and aesthetic

  • Inter is correct — de facto standard for trust-signaling B2B tools (alongside Geist Mono for data). ✓ Mock uses Inter
  • 1px borders over thick dividers — cleaner grid without visual bulk. ✓ Mock uses 1px borders
  • "Bubbly" rounded UI (large border-radius, pastel illustrations, soft shadows) now reads as low-capability. Our border-radius of 10px / 8px is correct — present but not dominant.
  • The "FinTech Aesthetic" (Vercel/Supabase/Mercury) — high-contrast type, near-monochrome surfaces, clean — is now the standard for tools targeting technical or enterprise buyers. Bid Factory's Cobalt and Precision Graphite themes are well-positioned here.

Micro-interactions

  • 200–500ms duration — long enough to register, short enough not to interrupt flow
  • Natural easing curves (acceleration + deceleration) — linear motion reads as robotic
  • Completion celebrations for task milestones (Asana's unicorn is the canonical B2B example)
  • Error states: a small "shake" animation communicates "no" without words
  • Always respect prefers-reduced-motion

What "feels like Linear" means in 2026

This is now the highest compliment in B2B design. It means: 0ms response to keyboard shortcuts (optimistic UI), every action reachable without mouse via ⌘K, information hierarchy reduced to 5 mental concepts max, full-screen modals instead of page navigation (preserves context), and natural language date parsing. The user never has to remember where something is.

Linear achieved this with specific engineering choices: switching from HSL to LCH color space for theme generation (perceptually uniform — we should evaluate this), and reducing their dark/light theme from 98 variable definitions to 3 variables (base color, accent, contrast).

§3 Manufacturing / CPQ UX Patterns

This is where the research is most directly actionable. These patterns are specific to estimating and quoting tools — not generic SaaS.

The "Excel-shaped" interface wins

The dominant mental model for manufacturing estimators is a spreadsheet: header metadata → line-item table → summary/totals. Any CPQ tool that departs from this shape faces adoption friction. Modern tools like Paperless Parts embrace this shape and make it faster — they don't reinvent it.

The Salesforce CPQ interface is the widely-cited negative example: rigid tab-within-tab-within-modal structure that forces users back through the same path repeatedly, leading to the "silent rejection" pattern where estimators revert to Excel.

Context collapse: the killer feature

Paperless Parts (the market benchmark for custom-part quoting UX) built their entire design around a single principle: the estimator should never leave the screen to do their job. Part geometry, RFQ details, cost build-up, and customer info are all on one screen. Every modal, tab-switch, or screen navigation is a cognitive interruption and a time cost.

Our mock has a good side-panel pattern for record detail — but the quote detail screen should more explicitly implement the side-by-side layout: drawing/part context on the left, cost build-up on the right.

This is the single largest gap in the current mock. Dense line-item tables are the core of estimating work. The current mock shows a basic table — here's what it needs:

AI in CPQ: eliminate setup, not judgment

The Paperless Parts model has strong market traction: AI handles the "secretary work" (extract dimensions from drawings, populate initial BOM, flag manufacturability issues) — the estimator applies expertise to the result. Estimators do not want AI pricing their jobs. They want AI removing the setup friction before they engage with the job.

Mobile in manufacturing

The research is clear: desktop-first for quoting is correct. Estimating and quoting is desk work requiring large screen real estate. No evidence of meaningful mobile CPQ usage. Shop floor tablet usage is significant but that's a different product surface. Bid Factory should remain desktop-first with no mobile quoting obligation in v1.

§4 AI / Wingman UX Patterns

The current mock uses purple for AI and has an activity feed with AI dots — both correct. But there are specific interaction patterns the research identifies that the mock doesn't yet show.

Where AI lives in the UI (placement hierarchy)

From best to worst placement for daily-use tools:

  1. Inline / contextual — appears where the user's cursor already is. Zero switching cost. (GitHub Copilot ghost text, Notion AI slash command)
  2. Side panel — parallel to the main workspace, for tasks where AI work is alongside primary work
  3. Command palette trigger — fires AI from wherever the user is, via ⌘K
  4. Floating button / persistent icon — weakest signal, competes for attention without context

The Governor Mechanism — the most important missing pattern

Any AI-generated content that appears in the quote (suggested price, suggested delivery date, DFM flag) should appear at reduced opacity until the user explicitly approves it. This is the Governor pattern — a human-in-the-loop checkpoint that doesn't interrupt flow but prevents silent AI errors from going unnoticed. Cursor's diff-preview-before-apply is the canonical implementation.

The "Why?" link — Progressive disclosure for explainability

Every AI recommendation shows a brief summary. A "Why?" link reveals the reasoning on demand. Linear uses this for AI-suggested priorities. It's never front-loaded, never forced. For Bid Factory: when Wingman suggests a price, a "Why?" link should reveal the reasoning (cycle time estimate, material cost, comparable jobs). This is the pattern that builds trust rather than eroding it.

Proactive AI: when to fire

From a 5-day field study of 15 developers with proactive AI (JetBrains/CMU, 2026): proactive suggestions fired mid-task were dismissed 62% of the time. The same suggestions at workflow boundaries (after saving, after completing a form, after a pause) achieved 52% engagement. For Bid Factory, this means Wingman fires proactively: after a STEP file is uploaded (DFM scan), after all line items are completed (margin check), after a quote is about to be sent (sanity check). Not while the estimator is mid-typing.

§6 Recommended Updates to BidFactory-LiveMock.html

⚡
P0 (implement next): Collapsible sidebar with hover tooltips and smooth animation. This is your explicit request and the single highest-impact change.

P0 — Collapsible sidebar changes

In BidFactory-LiveMock.html, the following changes are needed:

  1. CSS: add transition: width 260ms cubic-bezier(.4,0,.2,1) to .sidebar, add .sidebar.collapsed { width: 56px; }
  2. CSS: in collapsed state, hide .nav-label text and .logo-text, show only icons and logo mark
  3. CSS: tooltip positioning for collapsed icon hover (position: absolute; left: calc(100% + 8px))
  4. HTML: add a toggle button at the sidebar's right edge (the ◀/▶ chevron)
  5. JS: toggleSidebar() function that toggles the .collapsed class and writes state to localStorage
  6. JS: on page load, read localStorage.getItem('bf-sidebar-collapsed') and apply if set
  7. JS: document-level [ keyboard listener that calls toggleSidebar()

P1 — Line items table upgrade

  1. Add contenteditable="true" to Qty and Margin cells (with data-field attribute for change tracking)
  2. Add expand/collapse chevron column as first column
  3. Add hidden .operations-row TR after each line item that expands on click
  4. Style the expanded row distinctly (indent, smaller text, muted color)

P1 — AI Governor + "Why?" in Wingman affordances

  1. Any AI-suggested value in the quote detail (price, lead time, DFM flag) renders at 50% opacity initially
  2. An "Accept" micro-button and "Why?" link appear alongside the suggestion
  3. Accepting restores full opacity and adds an activity log entry
  4. Dismissing removes the suggestion and logs the dismissal

P2 — Shortcut hints in nav items

Add <span class="nav-shortcut">D</span> hints to sidebar nav items (Dashboard = D, Quotes = Q, etc.) visible on hover. These are distinct from command palette shortcuts — they're direct navigation keys, a power-user feature that should be discoverable but not distracting.
