BID FACTORY · UI DIRECTION

Shopify-class UI for a manufacturing CPQ

Research findings + concrete recommendations · 2026-06-13 · this document is rendered in the recommended design language — what you're reading is the proposed look.

⚠ Legal first — we cannot copy Polaris. Shopify's Polaris license (verified June 2026) restricts use to apps that integrate with Shopify; standalone apps must be "dissimilar and visually distinct from Shopify products … as determined by Shopify in its sole discretion." The React library is also archived (Jan 2026, maintenance-only). Recommendation: adopt the Polaris system (architecture, density, semantics) with our own identity tokens, built on Tailwind + shadcn/Radix. No Polaris packages, no pixel-cloning. Numeric values like a 13px body or a 4px spacing scale are facts and free to use; the black beveled buttons, exact palette, and nav treatment are Shopify's trade dress — ours diverge deliberately (orange primary, warm grays, flat controls).

1 · Why the Shopify admin feels the way it does

Shopify's 2023 redesign ("uplift", Polaris v12/v13) was built on four stated principles — these, not any specific color, are what we should steal:

PrincipleWhat it means concretelyBid Factory application
Calm density13px body text, 6px table-cell padding — spreadsheet-class density — kept calm by a gray canvas + white cards and 1px "edge" shadows instead of floating shadows.Perfect for estimating: costing grids, BOM trees and quote tables want density; cards keep an information-heavy quote editor scannable.
Color = meaning, never decorationThe UI is gray/white until something needs attention. Even the primary button is near-black. Status tones (green/yellow/red/blue) therefore pop instantly.Review items, DFM warnings, workflow statuses, inventory dots — our product lives on status. A neutral chrome makes them legible. Purple stays reserved for Wingman/AI (matches the demos).
PredictabilityEvery object gets the same triad: index page (saved views + table) → detail page (2-column cards) → same header pattern. Learn once, navigate anything.Quotes, Parts, Orders, Vendors, Rules, Processes — all follow the identical triad. This is also cheaper to build: one page recipe, instantiated eight times.
Explicit stateDirty-state save bar, skeleton screens shaped like the destination, black toast confirmations, banners for errors. The app always tells you what's happening.Critical for trust with skeptical Mittelstand users — especially around pricing recalculation ("Preise werden neu berechnet…", skeleton rows, then the new totals).

3 · The patterns, mapped to Bid Factory screens

3.1 · Index pages = saved views as tabs + dense table (Quotes, Parts, Orders, Vendors…)

Shopify's orders page is our spec'd saved-view engine: tabs are named saved filter+sort+column sets, user-creatable ("Save as" from edited filters). Filters render as dismissible pills. Row click navigates; checkbox selects; selection swaps the header for a bulk-actions bar (→ Bulk Edit Components, Update Thickness).

3.3 · The costing grid — the one thing Polaris doesn't have

Polaris has no editable data grid; Shopify edits via pages and modals. Our costing/operations tables need cell-level editing, per-qty columns, footer aggregation, drag-reorder. Recommendation: TanStack Table (headless, already in our stack) skinned with these tokens; AG Grid Community as fallback if virtualization/edit ergonomics demand it. Dense (5–6px cell padding), tabular numerals, unit price beneath totals, category color chips on costing rows (the demos' color-coding, kept).

3.4 · Contextual save bar — Shopify's most-loved pattern, ours too

Any dirty field on a detail/Configure page summons a dark bar (top-center): explicit save/discard, navigation blocked with confirm. Zero autosave ambiguity — exactly right for pricing data where a stray edit changes money. (BOM Builder keeps its spec'd draft-autosave; the save bar governs forms.)

3.7 · Where we deviate from Shopify on purpose

DeviationWhy
Side panels/drawers for record preview (Stripe pattern), not modal-everythingEstimators compare constantly. Clicking an operation, a review finding, or a vendor quote opens a right-side drawer over context — the spec's operation drawer already works this way. Modals reserved for true commitments (Bulk Edit warning, Create Rule).
Dark viewer canvases (CAD/PDF/nesting)CAD convention; model/drawing contrast; the demos' viewer look survives. The light chrome wraps a dark stage — like Figma.
Editable grids in-tableShopify edits via pages; estimators live in override cells. Single-click to edit, Tab across qty columns, calculated-vs-override styling (override values shown bold + underlined dot).
Orange primary + warm neutrals + flat controlsIdentity + the license's "visually distinct" requirement. Orange also survives on the shop floor (gloves, bad monitors, sunlight).
Purple = AI, everywhere and only AIContinues the demos' Wingman convention: purple badges, sparkles, suggestion cards. Users learn instantly: purple = machine-suggested, verify before money depends on it.

4 · Implementation plan

StepWhat
1Token file first: the CSS variables in this document become tokens.css + Tailwind theme config — single source of truth. No raw hex in components, ever.
2Component kit on shadcn/ui (Radix primitives) + Tailwind: Button, Badge (tone+shape), Card, PageHeader, Tabs/SavedViews, FilterPills, Banner, Toast, SaveBar, Drawer, Modal, EmptyState, Skeleton set, NavRail, CommandPalette (cmdk). ~2 weeks of Claude Code work; everything downstream gets faster.
3Grid layer: TanStack Table skin (dense theme, tabular nums, editable cells, footer aggregates, row drag). One implementation reused by quotes list, costing, operations, BOM, nesting overview.
4Page recipes: Index-page template + Detail-page template instantiated per entity. Storybook (or Ladle) catalog so every screen is built from cataloged parts — this is how the spec's 30+ screens stay consistent.
5Spec patch (on your go): Tech Stack section → light theme + this token sheet; add UI appendix reference; note the dark-viewer exception; acceptance criteria unchanged (layout fidelity to screenshots, not color fidelity).
