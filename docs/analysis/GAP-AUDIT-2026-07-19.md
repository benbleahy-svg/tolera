## Why this happened (probable mechanism)

The done-ledger `.autobuild.completed` stopped being appended after **M3.6 (Jul 15)** — everything after it relies on the driver's fallback name-matching, and driver logs on this machine also stop Jul 15 (the build has been driven from elsewhere since; this clone is a passive mirror, currently behind on `develop`). The 9 skipped blocks have **no PRs at all** — consistent with restarts using `--start <block>` jumping past them, or fallback done-detection misfiring. One skipped block (M3.13) was already caught and back-filled out of order (PR #82), which shows the queue *can* recover them — the other 9 just haven't been.

## Recommended fix order

1. **Before anything else: run M6.6** — M6.7c depends on it and it's the next visible gap in the vendor funnel you just built.
2. Rebuild the ledger from merged PR titles (one line per block id) so done-detection is trustworthy again, then let the driver walk the queue from the top — it should skip everything merged and pick up the 8 remaining skipped blocks in order: **M2.10 → M3.12 → M4.7b → M4.9b → M4.10b → M5.10 → M5.11 → M5.12**.
3. M2.10 needs a light re-scope before running: the panel container + identity/dims already exist from M3.2, so its block prompt should say "extend the existing `FoundInFilesPanel` Part-fields tab with the missing sections" rather than build from scratch.
4. Keep **M6.10** (14-demo replay) as the final catch-all — it would have caught most of this at the end, but fixing now avoids building M6.7b/c on missing dependencies.
