# M0.0 — Provisioning & Accounts (prerequisite gate)

**Not a coding block — a human-gated checklist to complete *before* M0.1.** This is the runbook for the pre-build provisioning session. Work top to bottom; the order is dependency- and lead-time-aware. Tick each box as you go.

> **The whole point:** three items have **lead time** and must be *started first* — the **Anthropic DPA** (signature can lag days), the **Google OAuth verification** (restricted `gmail.readonly` scope; review takes weeks), and **DNS/domain verification** (Mailgun + Clerk depend on it). Kick those off at the top of the session; everything else is same-day.

---

## 0. Where everything lives (read first — this is the rule)

Three tiers. **No secret ever goes in git.**

| Tier | Holds | Where | Notes |
|---|---|---|---|
| **1 · Password manager** (1Password recommended; Bitwarden fine) | every **account login**, **2FA/TOTP seed**, and the **master copy of every API key/secret** | a shared vault named **`Tolera`** | single source of truth for humans. Turn on 2FA for *every* account and store the recovery codes here. |
| **2 · Local dev** | the keys the app needs to run on your machine | a **`.env`** file at the repo root — **gitignored** | `.env.example` (names only, no values) **is** committed so anyone knows what's required. Docker Compose / pydantic-settings load `.env`. |
| **3 · CI + Prod** | the keys CI and the server need | **GitHub Actions encrypted secrets** (CI/deploy) + **Kamal secrets** injected at deploy (sourced from the vault) | never baked into the image, never committed. Use **separate dev vs prod/live keys** (Clerk, Mailgun, Anthropic all issue test + live keys). |

**Golden rules:** (1) commit `.env.example`, never `.env`; (2) confirm `.gitignore` contains `.env`, `.env.*`, `.kamal/secrets`, `*.pem`; (3) if a key is ever pasted into chat/commit/log, **rotate it**; (4) one vault item per service, with the login, 2FA, and its keys together.

✅ **Do this first:** create the `Tolera` vault now; create one empty item per service below; you'll fill each as you complete its row.

## 1. Domain — `tolera.eu`  ·  lead: registration instant, DNS minutes–hours
- [ ] Register **`tolera.eu`** at an EU registrar (or move DNS to Cloudflare for easier records).
- [ ] Plan the subdomains (decided in `DECISIONS.md`): **`app.tolera.eu`** (frontend), **`api.tolera.eu`** (backend/webhooks), **`rfq.tolera.eu`** (Mailgun inbound), root for marketing.
- **Unblocks:** Mailgun verification (§5), Clerk redirect URIs (§4), all customer-facing URLs + email from-addresses.
- **Capture → vault:** registrar login, DNS-provider login.

## 2. GitHub — private repo + branch protection  ·  lead: instant
- [ ] Create a **private** repo `tolera`; add it as the remote and push `main` (the repo already exists locally — see `bid-factory-repo-structure`).
- [ ] Create **`develop`**; set branch protection on **`main`** and **`develop`** (require PR + green CI, per the spec's Dev Workflow).
- [ ] Create empty **Actions secrets** placeholders (you'll fill at M0.1 / deploy): `KAMAL_REGISTRY_PASSWORD`, `SSH_DEPLOY_KEY`, prod env vars.
- **Unblocks:** M0.1 (CI), the one-PR-per-block workflow.
- **Capture → vault:** any Personal Access Token / deploy key. (Run the native `.git` cleanup first — see the README footnote.)

## 3. Hetzner — EU host + Postgres/Redis + object storage  ·  lead: account instant, servers on-demand
- [ ] Create a **Hetzner Cloud** account + project **`Tolera`**; pick an **EU location** (Nürnberg/Falkenstein/Helsinki) — this satisfies the "files never leave the EU" data-residency requirement (GDPR + dual-use).
- [ ] Generate a **Cloud API token** (for Kamal/provisioning) and add an **SSH key**.
- [ ] Create a **Hetzner Object Storage** bucket (S3-compatible, EU) for part/CAD files → get the **access key + secret + endpoint**.
- [ ] (Servers themselves can wait until M0.1's deploy step; create the project + token + bucket today. Postgres + Redis run in Docker on the app server — Hetzner has no managed Postgres.)
- **Unblocks:** M0.1 (deploy target), M4.0 (OCCT worker runs here), file storage, Kamal.
- **Capture → vault + secrets:** Hetzner login, **API token**, **SSH private key**; **S3** access key/secret/endpoint/bucket → `.env` (dev) + Kamal/CI (prod).

## 4. Clerk — auth (EU data residency)  ·  lead: instant  ·  *do after Google/MS (§7,§8) so SSO can be wired*
- [ ] Create a Clerk **application**; set **EU data residency**.
- [ ] Enable auth methods per `DECISIONS.md`: **password-primary + magic-link fallback + passkey**; enable **Google** and **Microsoft** SSO (paste the OAuth client IDs/secrets from §7 and §8).
- [ ] Set **redirect/allowed origins**: `http://localhost:5173` (dev) and `https://app.tolera.eu` (prod).
- [ ] Configure the session **JWT claim for active-org** (needed for the multi-org model, `DECISIONS.md` E4-a).
- [ ] Use the **Development instance** keys for now; create the **Production instance** when you deploy.
- **Unblocks:** M0.2 (tenancy/auth spine), M0.4 (shell).
- **Capture:** `CLERK_PUBLISHABLE_KEY` (frontend env), `CLERK_SECRET_KEY` (backend → `.env`/secrets), Clerk webhook signing secret (if used). Master copies → vault.

## 5. Mailgun — EU region (inbound RFQ + outbound)  ·  lead: DNS verify minutes–hours
- [ ] Create a **Mailgun** account, **EU region** (`api.eu.mailgun.net` — this matters for data residency).
- [ ] Add the domain **`rfq.tolera.eu`**; add the **DNS records Mailgun shows** at your registrar (MX, SPF `TXT`, DKIM `TXT`, tracking `CNAME`); wait for **verified**.
- [ ] Create an **Inbound Route**: match `.*@rfq.tolera.eu` → **store + POST to webhook** `https://api.tolera.eu/webhooks/mailgun` (placeholder until M3.3 deploys the endpoint; the route can exist now).
- [ ] Grab the **HTTP webhook signing key** (for verifying inbound) and the **sending API key**.
- **Unblocks:** M3.3 (email→quote ingest), M3.5 fallback, M5.5 (send), notifications. Pilot ingest address: **`fechner@rfq.tolera.eu`**.
- **Capture → `.env`/secrets + vault:** `MAILGUN_API_KEY`, `MAILGUN_DOMAIN=rfq.tolera.eu`, `MAILGUN_WEBHOOK_SIGNING_KEY`, `MAILGUN_BASE_URL=https://api.eu.mailgun.net`.

## 6. Anthropic — LLM provider + DPA  ·  ⚠ lead: **DPA signature can take days — start now**
- [ ] Create an **Anthropic Console** account.
- [ ] **Request and sign the DPA** (Data Processing Agreement) — via Console/sales. Needed for GDPR and for the M6.9 ROPA (sub-processor list). **Do this first thing.**
- [ ] Enable **zero-retention / no-training** handling if eligible; review data-processing terms.
- [ ] Create a **dev API key** (separate from prod later).
- [ ] Note the guard (already in the plan, M3.1): **export-control / dual-use-flagged files are never sent to any external LLM** regardless of settings.
- **Unblocks:** M3.1 (Lens extraction) + every AI feature (provider = Anthropic/Claude, per the folded decision).
- **Capture:** `ANTHROPIC_API_KEY` → `.env`/secrets; **signed DPA PDF** → vault + a `legal/` store; master key → vault.

## 7. Google Cloud — Gmail OAuth + Google SSO  ·  ⚠ lead: **verification = weeks; submit today**
- [ ] Create a **Google Cloud project** `Tolera`.
- [ ] Configure the **OAuth consent screen** (External): app name, support email, **authorized domain `tolera.eu`**, links to your privacy policy + ToS (host placeholders on `tolera.eu`).
- [ ] Add scopes: **`gmail.readonly`** (+ `gmail.send` if sending via Gmail) — these are **restricted** → trigger Google's security assessment; plus `openid email profile` for SSO.
- [ ] Create an **OAuth Client ID (Web application)**; redirect URIs = Clerk's Google-SSO callback + `https://api.tolera.eu/oauth/google/callback`.
- [ ] **For the pilot:** keep the app in **"Testing"** mode and add Fechner's users as **test users** (up to 100) — this works **without** the full review (users see a consent-warning screen, per `DECISIONS.md`).
- [ ] **Also click "Publish" → submit for verification now** so GA isn't blocked by the multi-week restricted-scope review.
- **Unblocks:** M3.5 (Gmail two-way threading); Clerk Google SSO (§4).
- **Capture:** `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET` → `.env`/secrets + vault; client ID/secret also pasted into Clerk SSO.

## 8. Microsoft / Entra ID — Outlook OAuth + Microsoft SSO  ·  lead: instant–short
- [ ] Register an app in **Entra ID** (Azure AD).
- [ ] Add **Microsoft Graph delegated** permissions: `Mail.Read`, `Mail.Send`, `User.Read`, `offline_access`, `openid email profile`.
- [ ] Add redirect URIs (Clerk's Microsoft-SSO callback + `https://api.tolera.eu/oauth/ms/callback`); create a **client secret**; consider **multi-tenant** if customers use their own M365 (admin consent may be needed per tenant).
- **Unblocks:** M3.5 (Outlook threading); Clerk Microsoft SSO (§4).
- **Capture:** `MS_OAUTH_CLIENT_ID`, `MS_OAUTH_CLIENT_SECRET`, tenant info → `.env`/secrets + vault; into Clerk SSO.
