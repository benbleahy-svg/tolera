# M4 — Geometry & Manufacturing

**Spec:** [#milestones](../docs/spec/Bid-Factory-Build-Spec.html#milestones) (M4 row) · **Exit criteria (authoritative):** fixture sheet-metal STEP → bends/thickness/flat correct vs goldens; nest math matches hand-calc; fixture assembly PDF → published multi-level BOM; repeat-part fixture triggers the assembly banner, and the **Accept All** path imports the router **atomically with source tags**.

**Goal.** Stand up **GeometryService** — the OCCT-backed CAD-interrogation engine — and everything it feeds: per-family feature recognition + DFM warnings, the sheet-metal flatten + nesting pricing path, the assembly BOM Builder, purchased-component Smart Match, auto-routing, and the two repeat-part AI features. This is the **highest-uncertainty milestone in the plan**: pythonocc is *unproven* against the spec'd feature catalogue (feature recognition, sheet-metal unfold, milling setup-detection, tube cross-section classification, the deterministic geometry signature are all genuinely risky). So M4 **opens with a spike** (M4.0) and every block whose approach depends on what OCCT actually returns stays **thin behind it** until the capability map exists.

**Golden-thread role.** M4 **replaces the thread's manual-dims mock** with real interrogation: from M4.1 on, the golden-thread part's `size_*` / `volume` / `area` / `weight` come from `GeometryService.analyze()`, not the hand-entered `PartGeometry` from M1.5. The pricing figures must still reproduce (the geometry→Kalk contract `PartGeometry-Attribute-Catalog.md` is the seam, unchanged), so the thread test stays green — it only gets *more real*.

> **The interface boundary is sacred.** Decision (folded): Spatial/HOOPS licensing was deferred → **OCCT-only for v1**; Spatial swaps in post-pilot **behind an UNCHANGED `GeometryService` interface** (../docs/decisions/DECISIONS.md). So M4 spends its design effort on the *contract* (the `AnalysisResult` schema, the `analyze_*()` signatures, `PartGeometry` field names/units) — those are pinned and must not bake in OCCT specifics — and treats the recognizer internals as swappable. Decision (folded): MBD/PMI viewing is **post-pilot deferred** (OCCT cannot) — `extract_pmi()` stays a stub. Per decision, the OCCT spike **heads M4** (not pulled early).

**Sequence:** `M4.0 (SPIKE)` → then the engine spine `M4.1 → M4.2 → M4.3` (dims/signature → sheet-metal unfold → nesting) with the per-family recognizers `M4.4 ⟂ M4.5 ⟂ M4.6` branchable in parallel once M4.0 lands → `M4.7 → M4.8` (DFM engine → custom interrogations) → the assembly track `M4.9 ⟂ M4.9b → M4.10 → M4.10b` (BOM Builder · CAD-assembly ingest → assembly components/Smart Match/auto-routing → quote-inclusion filter) → `M4.11` (Part-Library signature indexing, feeds M2) → the AI track `M4.12 ⟂ M4.13`. **Every block below M4.0 except M4.11's hashing scaffold and the AI blocks declares `Depends on: M4.0`** — its internals are gated on the capability map and may need its own mini-spike (called out per block).

### M4.0 — OCCT capability probe   `[SPIKE]`  · SPIKE-FIRST
- **Vertical slice:** for each Core-4 family, establish **what OCCT/pythonocc actually returns vs. the spec'd catalogue** — and decide go-with-OCCT or open the Spatial conversation.
- **Scope (in):** throwaway probes against **5–10 ground-truth STEP fixtures** (≥1 per family + 1 small assembly), measuring OCCT's real reach on the risky items: (a) dims/volume/area + **deterministic geometry signature** (does the same solid across two CAD exports / a split-vs-single face hash identically?); (b) **sheet-metal unfold** (can it flatten + recover thickness/bend count/bend radius?); (c) **milling setup-detection + runtime/confidence** (the honest-ceiling item); (d) **tube cross-section classification** (the 5 profiles); (e) `decompose_bom` on an assembly STEP. Output is **knowledge**: a per-family **capability map** (`family → scalar/feature → OCCT: ✓ / ~ / ✗ + note`) cross-walked to the `PartGeometry` v1 column and the `family_scalars` lists, plus a **greenlight-or-Spatial** recommendation per family and a thin throwaway `pythonocc` scaffold proving the import/parse path on Hetzner.
- **Scope (out):** any production recognizer, DFM eval, persistence, caching, the `GeometryService` API surface (all → M4.1+). No fabricated thresholds — where OCCT can't do something, that is the *finding*, not a number to invent.
- **Depends on:** M1 (golden-thread + fixtures harness); needs ≥5 STEP fixtures (Fechner packages, ../docs/decisions/DECISIONS.md → *Fixture packages*) — synthetic STEPs acceptable to start.
- **Implements (spec):** [#geometry-engine](../docs/spec/Bid-Factory-Build-Spec.html#geometry-engine) (Hybrid/OCCT-first decision), [#geometryservice](../docs/spec/Bid-Factory-Build-Spec.html#geometryservice)
- **Internals (provenance):** ../docs/spec/folded-subspecs/INTERROGATION-ENGINE-SPEC.md (§6 v1 OCCT scope + honest ceilings; §2 `AnalysisResult`; §1 service interface)
- **KB:** [KB: interrogations-basics](https://help.paperlessparts.com/s/article/interrogations-basics)
- **Decisions:** ../docs/decisions/DECISIONS.md → *Geometry engine = OCCT v1, Spatial swap-in behind an unchanged `GeometryService` interface* (the probe's job is to confirm OCCT clears the bar **or** trigger Spatial procurement, which has lead time)
- **Acceptance criteria:** a written capability map covers all Core-4 families against the `family_scalars` + `PartGeometry` v1 lists; the signature probe reports whether OCCT yields a **stable, topology-tolerant** hash on the test pair (the make-or-break for M4.1/M4.11); each family carries an explicit **OCCT-sufficient / needs-mini-spike / Spatial-required** verdict; if any Core-4 family is Spatial-required, an `OPEN:` is logged so procurement can start.
- **Test plan (fixtures):** the probe scripts run against `/fixtures/cad` and emit the map as the artifact — this is a knowledge spike, not a CI test; the map becomes the acceptance checklist M4.1–M4.6 build against.
- **Golden-thread role:** **de-risks the whole milestone** — confirms the engine can supply the real dims that replace the thread's manual mock (M4.1), or re-routes to Spatial before feature work begins.

### M4.1 — GeometryService core: dimensions + geometry signature   `[M]`

- **Scope (out):** any `family_scalars` / `features` / `feedback` (per-family → M4.2/M4.4–M4.6/M4.7); non-`✓` (`man`/`asm`) attributes (manual UI already exists from M1.5); the similarity vector (→ M4.11).
- **Depends on:** M4.0

- **KB:** [KB: interrogations-basics](https://help.paperlessparts.com/s/article/interrogations-basics)

- **Acceptance criteria:** a fixture STEP yields `size_*`/`volume`/`area`/`weight` within the Part-2 geometry tolerance vs its golden; `compute_signature()` returns the **same hash** for the M4.0 topology-variant pair (or, if M4.0 found OCCT can't, the limitation is recorded and the Exact-Geometric bucket is marked degraded for M4.11); metric stored, convertible for Kalk `units_in()`.
- **Test plan (fixtures):** golden `AnalysisResult.dimensions` assertion per fixture; a determinism test (same body → identical signature across N runs, mirroring the M1.8 determinism discipline).

### M4.4 — Milling setup-detection + runtime estimation   `[M]`  ⟂  *(thin — internals pending M4.0; may need its own mini-spike)*

- **Scope (out):** milling DFM warnings (deep-hole/deep-cut/small-radius → M4.7); **5-axis runtime is explicitly NOT auto-costed** — manual override is the designed path (honest ceiling); operation-generation auto-routing (→ M4.10).
- **Depends on:** M4.0, M4.1
- **Implements (spec):** [#geometryservice](../docs/spec/Bid-Factory-Build-Spec.html#geometryservice), [#interrogations-config](../docs/spec/Bid-Factory-Build-Spec.html#interrogations-config)
- **Internals (provenance):** ../docs/spec/folded-subspecs/INTERROGATION-ENGINE-SPEC.md (§2 Milling `family_scalars`; §3 milling feature catalog; §6 "5-axis runtime not auto-costed; low confidence → manual override")
- **KB:** [KB: milling-process](https://help.paperlessparts.com/s/article/milling-process)
- **Decisions:** ../docs/decisions/DECISIONS.md → *OCCT v1 reduced set* — **setup-detection + runtime estimation is a flagged-risky OCCT item (M4.0); internals stay thin and may need a dedicated mini-spike.** Surface `confidence` honestly; do not over-claim runtime accuracy.
- **Acceptance criteria:** a fixture mill body returns **K setups with per-setup runtime + a confidence rating** vs its golden (within tolerance / confidence band per Part 2); a low-confidence/complex fixture surfaces `confidence: Low` and leaves cost overridable rather than silently guessing.
- **Test plan (fixtures):** golden milling `AnalysisResult` (*this body → K setups, runtime R, confidence C*); a complex-part fixture asserts the low-confidence path.

### M4.7 — DFM warning engine (per-family threshold eval + Configure toggles)   `[L]`
- **Vertical slice:** the recognized features from M4.2/M4.4–M4.6 are evaluated against per-family thresholds to produce `feedback: Warning[]` — each carrying the **threshold that fired** — surfaced in the viewer and exposed to Kalk, with a Configure profile of seeded defaults.
- **Scope (in):** the DFM evaluator emitting `Warning {type, count, threshold_used, geometry_refs, can_disable}` per family; the **seed-default catalogue** loaded as the `Configure → Interrogations` profile, `family → warning → detects → threshold field(s) → default → enabled-by-default` exactly as the sub-spec table pins it (sheet-metal Small Cut 1.0×t, Close Cutouts 1.0 laser/2.0 punch, bend-relief 1.5/2.0×t, K-factor; milling Deep Hole 8.0, Small Internal Radius 1/32 in, Small Hole 1/16 in, slanted-hole 0.035 rad; lathe slender 8.0, bore-relief 0.25; tube angled-cut 45°…); the per-warning `should_detect_*` toggles in Configure; **always-on enforcement** (sheet-metal "Additional Operations Required", milling "Uncut Faces" cannot be disabled); the viewer right-panel Manufacturability Warnings list (severity dot + count + ⓘ, expand to per-instance rows).
- **Scope (out):** material-specific threshold overrides + custom-interrogation binding/resolution (→ M4.8); rules-engine consumption of warnings as review signals (the **Rules engine is M3** — this block only *emits* the signals it reads); the AI requote diff over findings (→ M4.12).
- **Depends on:** M4.2, M4.4 *(M4.5/M4.6 warnings fold in as those families land — branchable)*
- **Implements (spec):** [#dfm-catalogue](../docs/spec/Bid-Factory-Build-Spec.html#dfm-catalogue), [#interrogations-config](../docs/spec/Bid-Factory-Build-Spec.html#interrogations-config)
- **Internals (provenance):** ../docs/spec/folded-subspecs/DFM-WARNINGS.md (the full per-family threshold tables + defaults + toggle defaults + always-on list — pinned, do not re-derive)
- **KB:** [KB: sheet-metal-interrogation](https://help.paperlessparts.com/s/article/sheet-metal-interrogation), [KB: milling-process](https://help.paperlessparts.com/s/article/milling-process)
- **Decisions:** ../docs/decisions/DECISIONS.md → *OCCT v1 reduced set* — **gate each warning on whether its feature is detectable in v1**; if OCCT can't recognize the feature, mark the warning "v2/Spatial" rather than silently dropping it (a missing feature = a missing review signal). Thresholds are the sub-spec's published defaults — every one shop-calibratable; **do not invent values the sub-spec omits.**
- **Acceptance criteria:** a fixture with a known DFM violation raises the correct warning with the **firing threshold attached**; toggling a `should_detect_*` off suppresses it; an always-on warning **cannot** be disabled (enforced server-side); seeding yields the default profile with the catalogued thresholds; units stored as documented, presented metric-first.
- **Test plan (fixtures):** per-family DFM fixtures (e.g. a too-small bend radius, a deep hole) assert the warning + `threshold_used`; an always-on-disable attempt is rejected; a re-seed is idempotent.
- **Golden-thread role:** none directly; produces the interrogation **signals the M3 rules engine** turns into Review Items (M4 feeds M3, per the milestone graph).

### M4.8 — Custom interrogations + material-specific thresholds (most-specific resolution)   `[M]`

- **Depends on:** M4.7
- **Implements (spec):** [#interrogations-config](../docs/spec/Bid-Factory-Build-Spec.html#interrogations-config), [#dfm-catalogue](../docs/spec/Bid-Factory-Build-Spec.html#dfm-catalogue)
